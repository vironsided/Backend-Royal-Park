## Open Findings

### BUG-001 — FINDING-07 [P1-HIGH]: Public payment endpoints are still unauthenticated

**Status:** OPEN — not fixed in Phase 5

**Confirmation test:**
```
POST https://backend-production-9052.up.railway.app/api/payments/public
Content-Type: application/json
(no auth cookie)

{"resident_id": 999999, "amount_total": "0.01", "method": "CASH"}
→ HTTP 404 {"detail": "Resident not found"}
```
No session cookie was required. HTTP 404 confirms the endpoint is reachable and unauthenticated — it only fails because resident 999999 does not exist. With a valid `resident_id`, this endpoint creates a payment record without any authentication.

**Affected endpoints** (`backend_repo/app/routers/api_payments.py`):
- `POST /api/payments/public` (line 453)
- `GET /api/payments/{id}/open-invoices/public` (line 565)
- `POST /api/payments/{id}/auto-apply/public` (line 757)
- `POST /api/payments/{id}/applications/public` (line 926)

**Risk:** An attacker who knows any `resident_id` (easily enumerated from public apartment data) can create arbitrary payment records, apply them to invoices, mark invoices as paid without actual money changing hands, or inflate advance balances. This bypasses the entire financial integrity of the system.

**Recommended fix:** Add session-based auth check (`require_role(...)`) to all four `/public` endpoints, or remove them entirely if they are no longer needed for any integration.
